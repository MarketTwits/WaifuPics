# WaifuPics - Multiplatform Neko Images Application

## Overview

WaifuPics is a Kotlin Multiplatform (KMP) application for browsing random anime character (Neko) images via [NekosAPI v4](https://nekosapi.com/). Supports Android, iOS, Desktop (JVM), and Web (JS/WASM).

**Version**: 0.1.0
**Package**: com.markettwits.waifupics
**Repository**: https://github.com/MarketTwits/WaifuPics
**Web App**: https://markettwits.github.io/WaifuPics/

## Architecture

**Pattern**: Modular Clean Architecture with unidirectional dependency flow

```
instances/ (Android, iOS, Desktop, Web)
    ↓
features/ (Root, Random, Gallery, Navigation, About, Settings, Cache)
    ↓
core/ (Theme, Async, Cache, Cloud, CoreUI, Result, Paths, Image, Communication)
```

**Dependency Rules**:
- Instances → Features + Core
- Features → Core only
- Core modules are self-contained
- No circular dependencies
- Platform-specific code in source sets

### NekosAPI v4

## State Management

**Pattern**: StateCommunication (custom reactive state)

```kotlin
interface StateCommunication.State<T> { fun state(): StateFlow<T> }
interface StateCommunication.Mutable<T> : State<T> { fun map(value: T) }
```

**Key States**:
- `RandomImageState`: Initial | Progress | Success(RandomImageUi) | Error(message)
- `ImageState`: Loading | Success(id, url, width, height, protected) | Error(message)
- `FilterState`: filter: List&lt;FilterItem&gt;, isExpanded: Boolean

**Flow**: UI ← ViewModel ← Repository ← (API | Cache)

## Development Guidelines

### Creating a ViewModel
1. Define interface extending `StateCommunication.State<T>`
2. Implement as `ViewModel()` subclass
3. Create Communication class extending `StateCommunication.Abstract<T>`
4. Add to Koin module

### Adding a Screen
1. Add route to `Screen.kt`
2. Add composable to NavHost in `MainScreen.kt`
3. Create ViewModel + DI configuration
4. Implement UI composable

### Code Style
- Follow Kotlin conventions
- Prefer `val` over `var`
- Keep composables small and focused
- Use `remember`, `LaunchedEffect` appropriately
- ViewModels don't reference Composables
- Business logic in Repositories

## Common Issues

### CORS Error (Web)
Ensure `BASE_URL = "https://api.cors.lol/"` in NekoServiceBase.kt:37

### Images Not Loading
1. Check Ktor client setup in `core/cloud`
2. Verify Coil configuration in `core-ui`
3. Check network permissions (Android)

### Favorites Not Persisting
1. Verify KStore initialization
2. Check platform-specific storage permissions
3. Review ImagesCacheDataSource implementation

### Build Failures
- Clear cache: `./gradlew clean`
- Invalidate IDE caches
- Check heap size in gradle.properties: `-Xmx6048m`

## Performance Tips

- Use `LazyVerticalGrid` for galleries
- Implement proper `key()` for compose lists
- Enable Gradle build cache
- Use `derivedStateOf` to reduce recompositions
- Load appropriate image sizes (thumbnails vs full-screen)
